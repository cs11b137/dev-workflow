# 端到端验收

插件根目录 = 本 skill 目录的上两级。

## 1. 选定条目

1. 读 `docs/acceptance/acceptance-spec.md` 的 §1（口径）、§3.2（阻断级问题），以及参数指向的 §6 条目。没有参数时，列出 P0 条目请用户选择。
2. 为每个条目写下「必须观察到的结果」，作为检查清单。

## 2. 准备隔离环境

- 证据目录 `<E>` 放在仓库外（如 `$TMPDIR/acceptance-<主题>-<日期>/`），其中可以有子目录 `evidence/`、`screens/`、`logs/`。
- 使用隔离的数据目录、端口和配置，不碰用户的真实数据和全局设置；令牌等密钥只放在 `<E>` 里，权限 0600，不写进记录。
- 记录环境信息：分支、完整 SHA、系统与设备、组件和模型版本、夹具的来源与许可。

## 3. 执行

逐条执行。每一项「必须观察到」的结果都要留下证据（回执、事件、文件、截图、日志），记下证据路径。中途发现缺陷时：

- 记录问题和原因；
- 用户授权当场修复的，按 `change` skill 修复后重跑该条，并在记录里同时保留修复前后的证据。

和验收前提不一致的地方（环境不同、条件不满足），如实写进「偏差」。

## 4. 写记录

按 `<插件根>/templates/extra/acceptance-record.md` 新建 `docs/acceptance/<主题>-e2e.md`：

- 结论只用三种：通过 / 未通过（原因与后续） / 未测（原因）。
- 用模拟模型或模拟服务完成的条目，结论写「流程通过，真实效果未验」。
- 人工判断的条目写明审阅人。

完成标准：清单上的每一项都有结论和证据路径；记录里没有密钥。

## 5. 收尾

用 `finish` skill 提交记录（`docs(acceptance): record <主题> e2e run`），并报告：各条结论、阻断级问题（有没有）、修复的 commit、下一步。
