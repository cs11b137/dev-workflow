# 场景：修 bug（实现对齐规格）

规格是对的，实现错了，所以规格保持原样。

1. 确认规格章节确实定义了期望行为。规格没写或写得含糊时，转 `spec-conflict.md`。
2. 先写一个测试，复现原来的失败场景，并确认它在修复前失败（red）。
3. 修实现，直到这个测试通过，相邻测试也通过。
4. 涉及语言分支、平台分支或系统集成时，按 `docs/development-workflow.md` §4 覆盖兜底路径；没有实机的平台列为未测。
5. 用 `fix(<scope>)` 提交；同类修复沿用已有 scope（`git log --format=%s | grep '^fix('` 查找）。

完成标准：复现测试修复前失败、修复后通过；规格文件没有改动（除非已转 spec-conflict 并获裁决）。
