# 场景：有意改变协议、格式或公开行为

公开行为包括参数、默认值、错误码、退出语义、JSON 输出、持久格式与协议消息。

1. 确认任务确实授权改变这个行为。没有授权就转 `spec-conflict.md`，先报告。
2. 改写规格中拥有该行为的那一节（整合，不在文末追加）；有版本字段时按规格的兼容规则升版本。
3. 改实现。
4. 改测试：合同测试覆盖新形状与语义；不兼容的旧输入有明确拒绝或迁移的测试。
5. 同步受影响的 README 与使用说明。
6. 规格、实现、测试、README 放在**同一个** commit。破坏兼容用 `feat(<scope>)!:` 或 `fix(<scope>)!:`，正文写 `BREAKING CHANGE:`，说明影响与迁移方式。

完成标准：`git show --stat HEAD` 同时包含规格、实现、测试文件；`audit.py` 没有 ERROR。
