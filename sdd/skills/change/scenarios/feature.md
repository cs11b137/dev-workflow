# 场景：新功能（规格先行）

规格写完、用户审过，再写代码。

1. **产品设计**：在 §10 需求清单加一行 `<缩写>-nn`（等级、位置、验收列先留空）；用户可见流程在 §9 加一个 `Snn` 工作流（用户意图 / 过程 / 之后的修改 / 边界）；功能章节写行为，标题后标〔需求 ID〕。
2. **架构设计**：新增模块、改变状态所有权或做了取舍时，在 §1.3 决定表加 `Dnn`（决定、理由与约束、展开章节）。没有架构影响就跳过并在交付说明里写明。
3. **格式与协议**：新的持久格式、DTO 或协议，按 `<插件根>/templates/extra/spec.md` 新建 `docs/spec/<主题>-spec.md`，在 `docs/spec/README.md` 和 `docs/README.md` 阅读路线各登记一行。
4. **验收**：在验收与测试 §6 加 `AT-nn` 等条目（场景、必须观察到的结果、对应需求），回填需求行的「验收」列。
5. **审计**：`python3 <插件根>/scripts/audit.py`，修到没有 ERROR，新 ID 都没有 WARN。
6. **用户审阅**：提交规格（`docs(<scope>): specify <功能>`），交付说明列出新增的需求、决定、验收 ID，请用户审阅。

完成标准：每个新需求 ID 至少对应一个验收 ID，审计通过，用户已明确确认规格。

用户确认后继续实现：有 UI 走 `ui.md`；没有 UI 就实现 + 补测试（每个 P0 验收条目至少一个自动测试或写明人工验收方式），然后进入 `finish`。
