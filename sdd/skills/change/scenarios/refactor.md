# 场景：重构或性能优化

外部行为保持不变。一旦公开行为会变，转 `contract.md`。

1. 动手前跑一遍受影响模块的测试，记下基线结果。
2. 重构时遵守仓库约定：按领域命名，入口保持轻薄，权威逻辑只在其所有者模块里实现一次。
3. 改完再跑同一组测试，结果与基线一致。
4. 性能优化：用 `docs/development-workflow.md` §2 的基准入口，改动前后交替测量，同时记录机器负载与环境；报告比值，不报单次绝对值。
5. 用 `refactor(<scope>)` 或 `perf(<scope>)` 提交。

完成标准：前后测试结果一致；性能改动有交替测量的数据。
