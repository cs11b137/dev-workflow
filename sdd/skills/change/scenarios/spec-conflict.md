# 场景：规格缺漏、冲突，或需要产品决定

产品决定归用户。代理负责把差异讲清楚。

1. 记录每一处差异：文档与 § 号、规格写了什么、实现做了什么（或规格缺什么）、各自的影响。
2. 规格与实现都保持原样，除非这次任务明确授权了这项产品决定。
3. 给出 2–3 个选项和推荐，每个选项写清改哪边、影响范围。
4. 写进交付说明的「与规格的差异」一节，请用户裁决。任务的其余部分不受影响时可以继续完成。
5. 裁决后：
   - 改规格 → 按 `docs.md` 改写所属章节；行为随之变化时走 `contract.md`。
   - 改实现 → 走 `bugfix.md`。
   - 暂不决定 → 写进所属文档末尾的「待评审事项」。

完成标准：每处差异都有章节号和明确去向（已裁决 / 待评审事项）。
