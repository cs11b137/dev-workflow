# 本地 / 手动发布与续发

只在用户明确要求时使用。严格按用户指定的平台和范围执行：要求「只在本地」的，就只交付本地候选版，不公开发布。

## 本地候选版

1. 冻结完整源码 SHA，确认工作区干净（`git status --porcelain` 输出为空）。
2. 按项目的打包文档构建所要求的平台；记录构建命令与环境。
3. 对产物做自检（启动、版本号、签名状态），记录结果。
4. 在本地整理更新日志（`release-notes.md` 的「确定范围」与「分批总结」两节），不发布。
5. 报告产物路径、SHA、自检结果与未测项。

## 公开手动发布

1. 走完本地候选版的步骤。
2. 取得本任务的发布授权后，创建 release 并上传产物：`gh release create <tag> --target <sha> --notes-file <notes> <产物...>`。
3. 执行 `docs/release.md` §3 的读回检查，再标记 Latest 并读回。

## 单平台续发

1. 复用该版本已有的 tag、SHA 和更新日志范围；不重新生成更新日志，只补充平台说明。
2. 从同一个 SHA 构建缺失的平台，上传到已有的 release：`gh release upload <tag> <产物>`。
3. 读回该平台的资源和更新源。存在更新的版本时，Latest 保持不变。
