## 1. 口径

### 1.1 条目是定义，不是结果

本文的每一条验收都是**待实施的验收合同**。条目写在这里，只表示它是要求。

- 执行状态由测试记录维护（执行记录放在本目录的 `<主题>-e2e.md`）。
- 公式复算、文档检查或静态核对，只证明文档自洽；产品是否通过以对实现的测试为准。
- 某项能力尚未开放时，对应条目标为「不适用（能力关闭）」，并确认该能力在所有入口确实被禁用。

### 1.2 等级

| 等级 | 何时生效 |
| --- | --- |
| P0 | 首个完整闭环发布前必须通过 |
| P1 | 对应的能力开放时生效 |
| G | 对任何已开放的功能都生效，不因阶段而豁免 |

### 1.3 条目分组

| 前缀 | 范围 | 位置 |
| --- | --- | --- |
| `AT` | 产品行为：用户能观察到的结果 | §6.1 |
| `UI` | 界面结构与交互 | §6.2 |
| `A` | 架构：并发、断线、崩溃、升级 | §6.3 |
| `C` | 一致性：提交安全、幂等、身份 | §6.4 |

### 1.4 一条验收怎样才算通过

- 「必须观察到」的每一项结果都被观察到，并且有记录可查（回执、事件、文件、截图的引用）。
- 没有出现 §3.2 列出的阻断级问题。
- 记录中写明执行环境：操作系统与设备、相关组件与模型的版本、使用的夹具。
- 涉及人工判断的条目有审阅人与问题分级。

## 3. 发布门槛

### 3.1 门槛

发布一个阶段，必须同时满足：

1. 开放范围内的全部 G 条目通过；
2. 该阶段要求的 P0 条目通过（§3.3）；
3. 没有 §3.2 列出的阻断级问题；
4. 性能目标有实测记录（§4）；
5. 未开放的能力确实处于关闭状态，所有入口都不宣称能够执行。

### 3.2 阻断级问题

出现以下任何一项，不得发布：

- 未经授权的数据外发；
- 已确认的用户数据丢失；
- 没有产物却报告成功；
- 结果被应用到错误的目标；
