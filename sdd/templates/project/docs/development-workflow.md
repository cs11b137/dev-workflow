## 1. 规范与实现

开始改动前，找到该行为所属的规范章节、实现与相邻测试。文档中的目标合同和当前实现状态分开判断：规格里有定义，只说明它是目标。

- 有意修改协议、格式或公开行为时，同一任务更新对应规范、实现与测试；涉及使用方式时同步相关 README。参数、默认值、错误码、退出语义和 JSON 输出都属于公开行为。
- 修复实现以满足现有规范时，规范保持原样。发现规格缺漏、相互冲突或已有实现偏离时，说明对应章节和差异；超出任务授权的产品决定交由用户裁决。
- 业务语义与状态所有权遵守[架构设计 §1](architecture/architecture-design.md#1-总体架构)；权威逻辑只在其所有者模块里实现一次，UI、脚本与其他客户端调用它。
- 文档按[写作规则](README.md#写作规则)整合到所属主题，一事一处。

### 1.1 提交分类

自动与手动提交都使用 `type(scope): summary`；type 与 scope 用英文，summary 与正文默认用英文。scope 是稳定的模块或功能主题名（lowercase-dashed），同一类修复的多个提交沿用同一个 scope，优先复用已有分类。

| type | 适用变化 |
| --- | --- |
| `feat` | 新增或扩展产品能力、用户可见行为 |
| `fix` | 修复缺陷，使行为符合预期 |
| `docs` | 文档、规范、开发代理指令或 skill 的说明变更 |
| `refactor` | 重构实现，不改变外部行为 |
| `perf` | 改善性能 |
| `test` | 仅新增或调整测试 |
| `build` | 构建、打包机制或依赖变化 |
| `ci` | 持续集成与发布工作流变化 |
| `chore` | 其他日常维护，如版本号更新 |
| `revert` | 撤销既有变更；正文注明被撤销的 commit 与原因 |

summary 写清动作、对象及关键结果（如 `fix(file-location): handle Windows extended paths`）。需要解释原因、影响或兼容性时写进正文；破坏兼容的变化在类型／scope 后加 `!`，并在正文用 `BREAKING CHANGE:` 写明影响与迁移方式。

每个 commit 表达一个可理解的变更目的。一个功能或修复及其对应文档、测试同属一个提交；互不相关的改动分开提交。

### 1.2 合并前提交整理

任务分支或 worktree 合并回 `main` 前，审阅该分支相对合入基线的全部改动，把开发过程中的尝试、补丁、修正归并为 1–N 条有意义的事项提交。数量由独立事项决定：同一功能或修复通常一条，多个独立事项保留少量分开的提交。

- 每条提交按 §1.1 命名，摘要描述最终交付结果，正文列出具体修复、限制、迁移要求与 PR／issue 依据，可直接作为 changelog 来源。
- 已撤销的尝试不写成最终能力；独立修复在归并时保留。
- 只整理本任务尚未合入的内容；`main`、已发布 tag、共享分支与他人提交保持原历史。
- 核对整理前后的净改动等价；处理冲突后按实际影响重新验证。分支整理不包含 push 授权。

- 构建成功、自动测试通过和视觉验收分别报告。UI 变化打开实际页面检查目标状态、交互与控制台；原型截图只证明原型。

- 开发启动脚本可能在构建失败后继续启动；以构建结果判定能力，窗口打开不算通过。
- 检查通过后，只在新增修改、失败或仍有疑点时扩大或重复验证。交付说明报告实际检查结果与已知未测项。

## 4. 语言与平台

- 产出语言优先采用用户明确要求，其次采用已记录偏好，再从任务上下文推断。代码或例子使用的语言不构成产品缺省。
- 按语言或文字分支时，未列语言有明确兜底。新增或修复此类行为时覆盖对应语言及兜底路径。
- 平台专属 API、依赖与后端通过目标配置或能力检测隔离；平台不可用时有明确行为。
- 修改文件打开与定位、系统菜单、外部程序启动等系统集成时，逐个审计目标平台；没有实机的平台列为未测。

## 5. 工作区与产物

- 依赖变化使用对应包管理器更新并提交 lockfile。
- 生成物通过生成入口重建后提交；无关的历史生成物不在本任务里暂存。
- 临时答案、截图、测试项目与媒体放仓库外的临时目录；有意维护的测试夹具放所属测试目录。
- 在当前任务所属检出中工作；任务前已有或并发出现的改动属于用户，保持原样（不用裸 `git stash` 收走）。
- 每个 worktree 使用独立的构建目录与预览端口；预览服务读取本次修改的资源，确认它指向当前检出。
- 收尾停止本任务启动的服务；worktree、分支与专用构建目录按[强制完成门](../AGENTS.md#强制完成门)处理，只清理本任务拥有的资源。
